# 服务器部署准备

本轮只实现并验证本地应用，不连接或更改现有服务器。正式部署时采用一个 Node.js 24 进程、一个本地 SQLite 文件，前面接 HTTPS 反向代理。

## 初始化与目录

1. 在本机运行 `npm start`，通过页面完成访问密码设置。
2. 停止本地服务。把项目代码及需要使用的 `data/` 目录复制到服务器，不复制旧订阅项目的数据库。
3. 确保服务用户能写入 `data/`，数据库和 `access.json` 只允许服务用户读写。备份文件也应保持相同保护。
4. 服务器安装支持的 Node.js 24.x，直接 `npm start`，无需安装数据库服务或运行依赖。

也可在服务器仅监听回环地址的情况下，通过 SSH 端口转发从本机完成首次设置。不要在密码初始化前开放公网访问。

## 来源与 HTTPS

服务器 `.env` 示例：

```dotenv
HOST=127.0.0.1
PORT=3001
DATABASE_PATH=./data/accounts.sqlite
AUTH_PATH=./data/access.json
APP_ORIGIN=https://accounts.example.com
```

将域名替换为真实域名。`APP_ORIGIN` 必须是完整 HTTPS 来源，不包含路径或末尾斜杠。

反向代理需要：

- 对外提供有效的 HTTPS 证书，HTTP 重定向至 HTTPS。
- 将整个站点路径原样转发到 `http://127.0.0.1:3001`。
- 保留用户请求的 `Host` 与 `Origin`，不能把 Host 改成上游地址。
- 不缓存页面和 `/api/` 响应，不把项目根目录作为静态目录暴露。
- 仅通过代理开放公网访问，Node.js 默认保持回环监听。

APP_ORIGIN 配置错误会使 Host / Origin 校验拒绝请求；配置正确后会话 Cookie 自动启用 Secure。使用单个服务进程，不开启多 worker 模式，因为会话保存在进程内存中。

## 日常管理

用服务器现有进程管理方式启动 `npm start`，工作目录设置为项目目录，并配置进程异常退出后的重启。修改代码、前端资源或 `.env` 后重启应用；旧会话随之失效，用户需重新登录。

备份与恢复均先停止服务，复制完整 `data/` 目录及 `.env`；升级代码前先备份。SQLite 文件应位于该机器的持久磁盘上，不放在网络共享文件系统，也不与多个独立实例同时共享。

部署后验收：完成登录、新增一个账号、刷新页面、重启进程后再次登录，确认数据保留；验证公网无法下载数据库和密码哈希文件。
