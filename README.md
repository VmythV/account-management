# 归屿 · 个人账号档案

单人使用的 Web 账号管理工具。Node.js 24 + 本地 SQLite + 原生 HTML/CSS/JavaScript，保留已确认的页面设计。账号支持任意标识，可选加密保存密码；每次查看密码必须输入验证器动态验证码。

## 本地启动

需要 Node.js **24.19.0 或更高的 24.x 版本**。运行依赖由锁文件固定；无需单独安装数据库。

```sh
npm ci --ignore-scripts
npm start
```

打开 <http://127.0.0.1:3001>。首次访问时，在页面设置一个 **12–256 个字符的管理工具访问密码**，然后进入空账号库。数据库不会自动导入示例或旧项目数据。

后续使用同一个密码登录。管理工具访问密码仅保存加盐 scrypt 哈希，不保存明文。首次设置只开放给本机访问；服务器模式下未初始化密码会拒绝启动。

开发时使用 `npm run dev`；前端文件在服务启动时读取，修改前端后也需要重启服务。原页面原型保留在 [dist/index.html](dist/index.html)，可双击打开；该原型仍使用内存中的示例数据，与正式数据库独立。

## 功能与规则

- **账号库**：新增、编辑、搜索、归档和恢复。平台名称 + 完全相同的账号标识不能重复；同一平台可以管理多个不同账号。标识保留大小写语义，可填写用户名、邮箱、手机号或任意文本。注册日期未知时留空，系统另存录入时间。
- **标签**：选择已有标签或随账号创建新标签；管理页支持改名、自由选色和删除。名称与颜色同步应用到所有账号。多标签按交集筛选。删除标签只解除绑定，不删除账号。
- **关联**：来源账号 → 使用它注册、登录或恢复的账号。可新增、编辑和解除关系；支持多来源、多层链路和循环关系，禁止自身关联与完全重复的关系。图谱支持缩放、平移、聚焦与节点跳转，并提供键盘可访问的文字明细。
- **操作记录**：账号和关联变更自动留痕；手动记录可补录和更正。自动记录保留原始内容，需要改变账号或关联时使用对应的编辑入口。手动文字记录不会自动改变订阅状态。
- **订阅**：每个账号可以拥有多项订阅。可以修改订阅名称、记录新的变更、更正历史快照。状态包括订阅中、试用中、已暂停、已取消、已到期、被封禁。
- **保存**：服务端校验、外键约束和事务保证组合操作一起成功或一起回滚。编辑使用版本校验，其他标签页已修改的数据不会被静默覆盖。失败时保留弹窗内容；登录过期可用顶部“重新登录”在新标签页验证，再返回重试。

账号库每行右侧可直接进入账号详情；在详情页通过“编辑 → 账号状态”归档或恢复。网站地址可选填，仅接受 HTTP/HTTPS 网页地址，详情和关联速览中可在新标签页打开。第一版不永久删除账号，关联和历史记录会保留。

## 账号密码与双重验证

1. 打开“安全设置 → 绑定验证器”，输入管理工具访问密码，用兼容 TOTP 的验证器 App 扫码（也可手动输入密钥），再输入 6 位验证码确认。绑定信息 10 分钟内有效，二维码在本服务生成，不发送给第三方。
2. 在新增或编辑账号时选填密码，输入框右侧的“显示 / 隐藏”按钮可切换正在填写的内容，不读取已保存的密码。编辑时留空保留原密码；勾选“移除已保存的密码”才会清除。密码保留前后空格，不回填到编辑表单，也不会写入操作记录。
3. 在账号详情点击“验证后查看”，每次重新输入验证码。验证不解锁其他账号或后续查看；同一验证码只使用一次，需等待下一个 30 秒周期。显示后 30 秒自动隐藏，关闭弹窗、切换标签页或离开页面也会隐藏。

全站共用一个验证器。使用 TOTP/SHA-1、6 位、30 秒周期，接受前后一个周期的时钟偏差；服务器需启用时间同步。错误验证累计 5 次锁定 15 分钟，成功验证后清零；限流和已用时间步保存在 SQLite，重启、并发请求和不同登录会话不能绕过。登录仍使用管理工具访问密码，2FA 专门用于查看账号密码。

账号密码和 TOTP 密钥使用 AES-256-GCM 加密；每次生成随机 12 字节 nonce、16 字节认证标签，并绑定用途与账号 ID，交换密文或篡改会校验失败。`/api/archive` 只返回 `hasPassword` 与绑定状态；只有独立的 POST 查看接口在验证后返回单个密码，所有响应禁止缓存。存储加密不等于端到端加密：服务进程需要解密，掌握数据库和加密密钥的服务器管理员可以解密。

不提供恢复码，也没有网页关闭或更换验证器的入口。丢失验证器时，服务器所有者需先停止服务、备份数据库和密钥，再运行：

```sh
npm run reset-2fa -- --confirm-reset
```

重启服务并登录后重新绑定。重置不会解密或删除已保存密码，也不能跳过新验证器验证；管理工具访问密码仍需保留。服务器专用命令见 [部署文档](deploy/README.md)。

## 订阅历史与时间

每条订阅记录保存操作后的完整状态、等级、备注和续费规则。**按实际发生时间排序**，最新节点决定当前信息；补录较早节点不会覆盖最新状态。更正历史只改变该节点，重新计算累计时长。每项订阅的操作时间必须唯一，页面支持秒级填写。

- 只累计“订阅中”和“试用中”的时间区间，其余状态不累计。
- 例如 1 月 1 日开通、11 日暂停、21 日恢复、26 日取消，累计为 15 天。
- 操作时间按浏览器本地时区填写和展示，数据库保存 UTC；只允许记录已发生的操作。
- 注册日期是日历日期，不做时区转换。
- 续费提醒支持不设置、按月、按年。每月 29–31 日遇到短月取月末；2 月 29 日在非闰年取 2 月 28 日，后续仍使用原始规则。
- 仅订阅中、试用中显示提醒。页面每分钟及重新切回时更新时长和日历提醒。
- 提醒只表示日历日期，不判断是否已经付款、不自动标记逾期或改变状态，无邮件或推送通知。

## 数据、备份与恢复

默认文件：

| 路径 | 内容 |
| --- | --- |
| `data/accounts.sqlite` | 账号、标签、关联、操作记录、订阅和快照 |
| `data/access.json` | 管理工具密码的算法标识、盐和哈希 |
| `data/vault.key` | 默认加密密钥文件；线上单独存于配置目录 |
| `.env` | 可选的启动配置 |

数据库及密码哈希文件默认权限为 `0600`，新建数据目录为 `0700`，并已排除出版本控制。SQLite 中账号密码及验证器密钥字段已加密，账号标识、备注等其他数据未加密。加密密钥文件只允许 `0600` 或 `0640`，不进入仓库；已有密文时密钥缺失或不匹配会拒绝启动。

**备份**：停止服务并等待进程退出，备份数据库、访问密码哈希及 `.env`，另行备份 `VAULT_KEY_PATH` 指定的加密密钥。默认本机密钥位于 `data/vault.key`，异地备份时应与数据库分开保存。密钥丢失后，账号密码无法恢复，重置验证器也无效。**恢复**：停止服务，先备份当前文件，再替换为备份文件并启动。不要在服务写入期间只复制主 SQLite 文件。自动测试验证了关闭、复制、重新打开后的数据一致性。

**忘记或更换访问密码**：停止服务，将 `data/access.json` 移到安全备份位置；暂时关闭 `APP_ORIGIN` 并仅使用 `HOST=127.0.0.1` 启动，在本机重新设置密码。账号数据库保持原样。重新设置后再恢复服务器配置。密码重置由机器所有者操作，不开放远程无密码重置入口。

数据库使用 `PRAGMA user_version` 管理结构版本，当前为 3。版本 1 会先新增网站字段，版本 1/2 再新增密码密文表和验证器配置表；原有账号、网站、关联、记录和订阅保留，默认无密码、未绑定。程序遇到更高版本数据库会拒绝启动，避免旧程序写坏新结构。升级前应先备份。

## 配置与服务器部署

可复制 `.env.example` 为 `.env`，再按需修改：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 默认只监听本机 |
| `PORT` | `3001` | Web 服务端口 |
| `DATABASE_PATH` | `./data/accounts.sqlite` | 数据库路径 |
| `AUTH_PATH` | `./data/access.json` | 密码哈希文件路径 |
| `VAULT_KEY_PATH` | `./data/vault.key` | 32 字节加密密钥；线上与数据库分开保存 |
| `APP_ORIGIN` | 空 | 服务器部署时设置准确的 HTTPS 来源地址 |

相对路径均相对于项目目录，与启动时所在目录无关。详细部署要求见 [deploy/README.md](deploy/README.md)。

会话 Cookie 使用 HttpOnly、SameSite=Strict；配置 HTTPS 来源后启用 Secure。会话最长 7 天，锁定退出及服务重启后相关会话失效。登录失败会限流；写接口检查来源和 JSON 类型，限制请求大小。所有 SQL 参数绑定，文本转义渲染；数据文件不通过静态资源路由提供。

## 代码结构

| 文件 | 用途 |
| --- | --- |
| `server.mjs` | HTTP 路由、会话、初始化入口、静态资源 |
| `lib/auth.mjs` | 密码哈希生成、保存与验证 |
| `lib/store.mjs`、`lib/schema.sql` | SQLite 数据结构与业务写入 |
| `lib/validation.mjs` | 输入边界校验 |
| `lib/vault.mjs`、`lib/vault-schema.sql` | 密码加密、TOTP、限流和防重放 |
| `scripts/reset-2fa.mjs` | 停机后的服务器验证器重置 |
| `public/app.js`、`public/forms.js` | 页面渲染、表单与交互 |
| `public/data.js`、`public/timeline.js` | 接口数据、订阅快照计算 |
| `public/graphs.js`、`public/vendor/` | 关联图谱及离线组件 |
| `dist/` | 独立保留的设计原型 |

当前按单人、单进程工具实现；不包含多人协作、云同步、自动备份、自动续费或旧项目数据迁移。

实现核对了 Context7 中的 [Node.js SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html) 和 [crypto.scrypt](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback) 文档。`node:sqlite` 在 24.x 仍标记为候选发布接口，升级运行环境后需重新运行测试。图谱组件版本和许可证见 [vendor/README.md](public/vendor/README.md)。

密码功能核对了 Context7 中的 [Node.js crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html)、[OTPAuth](https://github.com/hectorm/otpauth) 和 [Node QRCode](https://github.com/soldair/node-qrcode) 官方文档；依赖精确版本与完整性摘要见 `package-lock.json`。
